# 大纲、章节骨架与多线叙事方案

本文在「作者在环、小颗粒回合、多角色独立 Agent」前提下，吸收唐库类产品在**多级大纲 / 章骨架**上的思路，并与本仓库已讨论定稿的叙事原则对齐：**正文以主角为主线**、**每角色在系统内仍是一条完整并列主线**、**大纲与节拍只做指导不限死死节奏**。

**关联文档**：

- [character-growth-state-machine.md](./character-growth-state-machine.md)：关键角色成长状态机、记忆分层、`GrowthGuard`；**主写角色内在演进**，与节拍标签弱绑定即可。
- [examples/relationship_graph.yaml](../examples/relationship_graph.yaml) / `src/runtime/relationship_graph.py`：**关系与证据**跨角色共享；正文只消费摘要时，图谱仍可记录因果证据（`evidence_events`）。

---

## 1. 目标与非目标

### 1.1 目标

- 提供**全书级 / 章级 / 节拍级**的结构化指导，注入写作前分析与正文生成，减少长线漂移。
- **节拍可跨多回合**（与当前小颗粒 `turn` 一致）；产品上建议**单节拍通常 1～2 回合、尽量少于 3 回合**，作为**软提示**，不写死为强制校验。
- **正文输出**：以**主角主线**为叙事主轴；其他角色的独立活动在主书中仅以**必要摘要**出现，用于推动剧情因果。
- **系统内真实多线**：除正文外，每个角色保持**长期独立活动记忆与规则**，逻辑上可随时导出为**同世界观下的另一本「同文小说」**（番外 / 角色列传），与主书设定与时间线对齐。

### 1.2 非目标

- 不替代现有「画卷徐徐展开」式单回合节奏控制。
- 不把大纲做成「必须本回合完成某情节点」的硬状态机（完成节拍以**作者在环**为主）。
- 第一阶段不要求自动拆分导入长文（epub 等）——可作为后续扩展。

---

## 2. 三层叙事架构

### 2.1 正文层（主书）

- **读者-facing 连续叙述**：镜头与篇幅以**主角**为锚；场景以当前 `scope` / 事件簿共识为主。
- **其他角色**：仅当**在场**或**桥接摘要**显式需要时进入叙述；避免在主书中展开全员平行长篇。

### 2.2 平行主线层（每角色一条「真主线」）

- 每个 `CharacterAgent` + 私有记忆（及后续成长状态、可选「屏外时间线」）承载该角色**完整**的欲望、行动、关系变化。
- 未在主书场中出现的戏份，以**记忆条目**（建议类型如 `off_screen` / `parallel_thread`，实现阶段再定）持续累积，而非丢弃。

### 2.3 桥接层

- 当主书下一场景依赖某角色屏外结果时，向正文管线注入**短摘要**（一两段或结构化片段），来源为该角色记忆（或轻量 LLM 压缩），**不**把副线全文拼进 `generate_turn_body`。
- 触发方式：**作者在环指令**、节拍元数据 `tags`（如 `cross_character`）、或后续轻量规则；默认**不**每回合自动灌入所有角色全文。

## 3. 大纲 / 章 / 节拍（指导关系）

| 层级 | 作用 | 与回合关系 |
|------|------|------------|
| **卷（可选）** | 长篇分段、主题弧 | 一卷多章 |
| **章（Chapter）** | 读者感知的章节单元；本章戏剧问题 / 情绪目标 | 一章多节拍、多回合 |
| **节拍（Beat）** | 最小剧情意图单元（本小段要推进的信息 / 冲突 / 关系） | **1 节拍 ↔ 1～N 回合**，建议 N&lt;3 |

**原则**：大纲与节拍是**主线指导**，不是限速器；角色成长与关系演进仍以 **事件 + 记忆 +（后续）成长状态机** 为准。

### 3.1 节拍与角色线

- **主线节拍**：描述「场上」戏剧意图（可与 `suggested_scope_id` / 时间地点建议对齐）。
- **角色挂钩（可选，MVP 可用轻量字段）**：`character_hooks: { 角色id: "本节拍对该角色意味着什么" }`。
- **演进路径**：后续可增设独立 `character_arcs.yaml`（每角色 `milestones[]`），与章/节拍**弱链接**，避免把每角色故事绑死在同一套 beat 编号上。

## 4. 数据落盘建议（小说目录）

与现有 `data/novels/<slug>/book/` 布局一致，建议新增：

- `book/outline/outline.yaml`：卷 / 章 / 节拍树 + 可选 `character_hooks` / `tags`。
- `book/outline/progress.yaml`（可选）：当前 `chapter_id` / `beat_id`、本节拍内已写回合数（用于「建议 &lt;3 回合」软提示）。

**无大纲文件时**：行为与当前版本完全一致（零侵入默认）。

## 5. 与现有代码的接入点（实现阶段执行）

1. **`generate_turn_plan_for_turn` / `build_turn_plan_prompt`**  
   注入：当前章标题、本章戏剧问题、当前节拍 `intent`、可选下一节拍一行预告；附一句「单节拍建议少于 3 回合，当前已为第 k 回合」类软提示。

2. **`generate_turn_body`**  
   明确 prompt 约束：**以主角为主线**；非主角仅在摘要或在场时展开；可注入桥接摘要块（若本回合标记需要）。

3. **`run_novel_with_author.py`**  
   每回合开始打印章/节拍进度；作者确认写回后**推进以作者显式指令为唯一**——每确认一个有效回合即 `turns_in_beat += 1`（事实记录），跨节拍/章由作者在环明确选择（`outline_store.advance_to_next_beat` + `save_progress`）。**只写 `progress.yaml` 指针迁移，不整树写 outline.yaml**（全量回写留 Phase 2）。

4. **`Orchestrator` / `MemoryStorage`**  
   主书事件仍入 `scope` 事件簿；屏外副线写入对应角色 `append_event_refinement`（或专用 API），与正文数据源分离、可追溯。

5. **关系图谱**  
   主书回合写回后继续维护 `co_presence` / 语义边；屏外线若影响关系，可在后续规则中写入边与 `evidence_events`（与成长状态机同哲学：**叙事语义优先**）。

6. **成长状态机**（落地后）  
   在 `apply_event_and_state_write` 之后按事件迁移；节拍 `tags` 仅作**可选触发提示**，不做硬编码数值跳变。

## 6. 「同文小说」导出（产品形态）

- **输入**：指定 `character_id` 的**长期记忆** + **关系子图（邻居摘要）** + **世界设定只读切片**。
- **输出**：独立 Markdown（或分章结构），叙事主角为该角色；与主书共享世界观与大事约束，主书未写部分在番外展开。
- **实现顺序**：大纲 MVP 之后单独任务（CLI 或脚本即可）。

## 7. 配置项建议（待定稿）

- **`runtime.novel_run.protagonist_id`** 或 **`characters[].is_protagonist`**：显式主角，供正文管线默认使用（需与 `enabled_ids` 一致）。
- **`runtime.outline`**（可选）：`enabled`、`path`（默认 `book/outline/outline.yaml`）、`soft_max_turns_per_beat`（默认 3，仅提示）。

## 8. 分阶段落地

**执行级拆解（范围、API 建议、验收清单）**：见 **[outline-mvp-plan.md](../planning/outline-mvp-plan.md)**。

| 阶段 | 内容 | 验收 |
|------|------|------|
| **MVP-0** | `outline.yaml` + `progress` schema、校验加载、日志打印 | 已实现 `outline_store` + 主流程 `[大纲]` 日志；无文件时行为不变 |
| **MVP-1** | 注入 `TurnPlan` / `generate_turn_body` | 分析与正文对齐当前节拍与主角轴 |
| **MVP-2** | CLI 进度、写回后更新 progress / beat 状态 | 重启可读进度 |
| **Phase 2** | 设定阶段后 LLM 生成大纲初稿 + 作者改 | 可手改后继续写 |
| **Phase 3** | 屏外记忆类型 + 桥接摘要触发 + 可选副轨低成本更新 | 主书仍主角轴 |
| **Phase 4** | 单角色同文导出 | 独立成书可读 |

## 9. 待拍板项（实现前可收敛）

1. 主角在配置中的**唯一显式字段**命名与校验规则。  
2. 屏外线更新是**按需 / 按标签**触发，还是**定时批处理**（成本与「平行线真实度」权衡）。  
3. 是否第一版即引入独立 `character_arcs.yaml`，或仅用节拍内 `character_hooks`。
