## 1. 背景与问题

### 1.1 现状

- 作者在环统一入口目标态为 **分类 →（按需）检索 → 单一组装点 → Handler**（见 **D6**）。  
- 当前 `src/author_loop/retrieve_for_intent.py` 在检索结果上采用 **按预算分配 + 字符截断（`_truncate`）+ 总预算兜底（`_enforce_total_budget`）**，保证延迟与费用可控，但属于 **硬截断**，不区分「任务主线」与「可铺陈信息」。  
- 作者在环 **任意输入**（菜单键、短命令、长段反馈、跑题句）与 **多阶段**（设定讨论、正篇审阅等）并存，**固定分层标签**（例如永远三层「世界/事件/digest」）无法在所有场景下表达「本轮到底要保什么」。

### 1.2 要解决的问题

1. **不能**将「上下文压缩」退化为 **无脑一段摘要**或**单句结论**，以免丢失 **过程性信息**（因果链、未决点、约束冲突）与 **结构**（来源块、顺序、节拍锚点）。  
2. **必须**在统一入口下 **自适应**：同一套机制能随 **意图、阶段、输入形态** 调整「什么是主线、什么是框架、什么可先压」。  
3. **必须**与现有 **预算上限** 兼容：语义压缩之后仍可保留 **硬上限** 作为最后保险。

## 2. 目标与非目标

### 2.1 目标

| ID | 描述 |
|----|------|
| **G1** | 在组装后的上下文字符/token 接近配置上限时，优先采用 **任务锚定、结构保留** 的压缩策略，而非仅截断尾部。 |
| **G2** | 每轮生成可审计的 **压缩契约（Compression Contract）**，明确本轮 **任务主线**、**结构保留要求**、**分层权重**与 **超预算时的牺牲顺序**。 |
| **G3** | 使用 **软原型（场景初值）+ 自适应修正**，避免单一固定框架套所有场景。 |
| **G4** | 输出仍为 **分块/带来源或分节** 的可注入文本，禁止默认压成 **单段结论文**。 |

### 2.2 非目标（现阶段）

- **不**规定具体选用哪家 LLM 或是否引入 **LLMLingua** 等小模型；实现阶段在 **D5** 与运行时配置中选型。  
- **不**替代 **U-1「检索完整方案」** 总册职责；本文只约束 **检索已发生之后** 的上下文治理，与 [next-iteration.md](../planning/next-iteration.md) **远期 U-1～U-5** 可互链增量修订。  
- **不**改变 **两阶段审阅** 等 L1 门禁；压缩仅作用于 **注入下游模型的上下文**，不绕过作者在环确认。

## 3. 核心方案：自适应分层任务锚定压缩

### 3.1 与「方案一」的关系

本 SDD 采用 **分层 + 任务锚定 + 结构保留** 的思想（见讨论稿），但 **不**将分层语义写死为全局唯一表，而是引入 **§4 压缩契约**，使分层 **每轮可变**。

### 3.2 压缩契约（Compression Contract）

每轮（或每次完成 `assemble_retrieval_prompt_block` / 等价组装之后）生成一份 **契约**，至少包含以下 **字段语义**（具体序列化格式实现时可选 JSON/YAML/Python dataclass）：

| 字段 | 说明 |
|------|------|
| **`task_thread`** | **本轮任务主线**（自然语言短句）：说明「系统在帮作者完成什么**过程**」，须由 **phase + intent + 用户输入摘要** 推导，**不是**剧情结局式概括。 |
| **`structure_preservation`** | 本轮必须保留的 **结构形式**（如：多 `【来源】` 标签、时间顺序列表、节拍/章节点）；**随场景变化**。 |
| **`layer_roles`** | **动态层**列表：每层含 `name`（如「作者要求」「检索证据」「digest」）、`importance`（权重或高/中/低）、`compress_strategy`（短写 / 抽句 / 仅保留锚点）。**不得**写死为全仓唯一的三层名称。 |
| **`sacrifice_order`** | 超预算时 **削减顺序**（先压哪类、后压哪类），避免一刀切成单段摘要。 |
| **`query_focus`** | 与 **`retrieval_query`** / 作者输入对齐的 **关注面**（关键词或短句），用于块内取舍。 |

契约可由 **规则模板 + 已有 `classify_intent` 结果** 生成；必要时再引入 **轻量 LLM 调用** 仅生成契约（比全文摘要便宜且可控）。

### 3.3 软原型（Soft Templates）与自适应修正

- 预置若干 **场景原型**（可与 `AuthorPhaseState.phase`、`intent_id` 对齐），例如：`DESIGN_DISCUSSION`、`MAIN_WRITING_REVIEW`、`SAVE_PROGRESS`、**通用兜底**。  
- 每个原型仅提供：**默认 `layer_roles` 初值**、**默认 `structure_preservation`**、**默认 `sacrifice_order`**。  
- **自适应修正**信号（非穷尽）：  
  - 用户输入 **极短**（如 `y`/`n`）→ 契约可 **极简**，检索块压缩需求低；  
  - 用户输入 **极长** → 提高 **「作者原句」层** 权重，检索块更易被压缩；  
  - **分类置信度低** → **不**强行套用复杂分层，退化为 **最小安全集**：**任务句 + 用户原句（或截断）+ 来源标签骨架 + 少量事实锚点**。

### 3.4 分块压缩约束

对每个语义块执行压缩时，提示须包含：

- 该块在 **`layer_roles` 中的角色**；  
- 全局 **`task_thread` + `query_focus`**；  
- **禁止项**：如禁止「输出跨块全文结论」「仅输出一句故事梗概」；  
- **必须项**：若该块承担 **顺序/结构**，保留 **条目级骨架**（编号或小标题）。

## 4. 与现有代码的挂载点（目标态）

| 环节 | 建议位置 | 说明 |
|------|----------|------|
| 契约输入 | `classify_intent` / `apply_*_ingress` 之后 | 已有 **intent、phase、retrieval_query**。 |
| 组装后 | `assemble_retrieval_prompt_block` 或 PromptAssembler 出口之后 | 得到 **完整待注入字符串** 或 **片段列表**。 |
| 门限 | 配置：`retrieve_max_total_chars` 或独立 **`context_compress_threshold_ratio`**（建议 **0.75**） | 超过 **阈值 × 上限** 时触发压缩管线。 |
| 硬保险 | 现有 `_enforce_total_budget` 或等价 | 语义压缩后仍 **不得超过** L1 约定之总预算。 |

当前 **`retrieve_for_intent`** 内 **字符截断** 保留为 **fallback**；引入本方案后，优先路径为 **契约驱动压缩 → 再 enforce**。

## 5. 门限、滞回与可观测

- **触发**：当 `len(assembled_context)`（或 token 计数） **≥ threshold_ratio × cap**（建议 **0.75**）时，进入压缩管线。  
- **滞回**：压缩至 **≤ 约 0.5 × cap** 再结束迭代，避免在边界反复压缩。  
- **可观测**（与 D6 **H4** 一致）：日志中记录 **是否触发压缩**、**契约摘要（intent、原型 id、layer 权重哈希或简表）**、**压缩前后字符数**；单测可断言「非单段结论格式」的子串或结构。
